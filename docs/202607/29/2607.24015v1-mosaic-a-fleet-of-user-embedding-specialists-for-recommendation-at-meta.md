## 摘要
在工业推荐系统中，用户表示是杠杆作用最高的建模问题之一：用户编码方式的单一进步可以在平台规模上传播到检索、排序和完整性任务。先前的工业用户表示工作要么构建一个输出一个或多个嵌入向量的单一用户模型，要么构建一个具有任务特定适配的共享主干网络。在本文中，我们提出Mosaic，一个基础用户建模平台，采用专家集群来学习用户嵌入。该集群包含四个架构多样的模型家族——记忆驱动型、密集重型、序列基型以及CoTrain模型——每个专注于用户行为的不同方面。我们开发了MRM（多任务关系挖掘）和CRL（余弦冗余损失）技术，以最大化每个新专家的边际信息贡献。我们还引入了CoEval和User Tower Zero-Out，一种新的无需日志记录的嵌入评估框架，它在保持下游对齐准确性的同时提高了开发速度。我们的混合CPU/GPU、在线和离线服务栈允许每个专家选择适当的服务策略以满足新鲜度、延迟和计算要求。Mosaic在在线收益之外还提供了持续且显著的离线NE改进。

## Abstract
User representation is one of the highest-leverage modeling problems in industrial recommendation systems: a single advancement in how users are encoded can propagate across retrieval, ranking, and integrity tasks at platform scale. Prior industrial user representation work builds either a single user model that emits one or more embedding vectors or a shared backbone with task-specific adaptation. In this paper, we present Mosaic, a foundational user modeling platform that employs a fleet of specialists to learn user embeddings. The fleet comprises four architecturally diverse model families - memorization-driven, dense-heavy, sequential-based, and CoTrain models - each focusing on a distinct facet of user behavior. We developed MRM (Multi-task Relations Mining) and CRL (Cosine Redundancy Loss) techniques to maximize the marginal information contribution of each new specialist. We also introduce CoEval and User Tower Zero-Out, new logging-free embedding evaluation framework that improves development velocity while preserving downstream-aligned accuracy. Our hybrid CPU/GPU, online-and-offline serving stack allows each specialist to choose the adequate serving strategy to meet the freshness, latency, and computational requirements. Mosaic delivers consistent and significant offline NE improvements in addition to online gains.

## 1. 论文的核心问题与整体含义（研究动机和背景）

工业推荐系统中，用户表示是最具杠杆作用的建模问题之一。现有方法主要有两类：一是构建单一用户模型输出一个或多个嵌入向量，二是采用共享主干网络加任务特定适配。然而，这些方法难以同时捕捉用户行为的不同侧面（如稀疏ID、密集计数、时序序列、跨表面信号），导致表征覆盖不均，尤其在冷启用户上性能更差。Mosaic 提出**用户嵌入专家集群**的设计范式——用多个异构的专门化模型分别学习不同维度的用户行为，并通过统一平台进行训练、评估和服务，从而在平台规模上提升检索、排序和完整性任务的效果。

## 2. 论文提出的方法论：核心思想、关键技术细节

**核心思想**：将用户表示管理为一组异构的专家模型（specialist fleet），每个专家专注于一类用户信号，并独立训练与服务。

**四类专家模型家族**：
- **记忆驱动型（Memorization-driven）**：利用超大尺寸哈希表捕捉细粒度用户偏好，服务时采用表批处理嵌入（TBE）、分层存储（GPU HBM/CPU DRAM/SSD）、INT4量化；交互网络保持简洁。
- **密集重型（Dense-heavy）**：输入丰富聚合计数特征（多时间窗口、多行为类型、多表面），通过非线性特征交叉（MHTA、SEDot、Wukong）学习，输出多个嵌入。
- **序列型（Sequential-based）**：基于 HSTU Transformer，加入上下文 token、用户交互历史 token 交错（UIH）以及分层注意力；使用随机长度训练解决训练/服务序列长度差异；支持 MoE 路由扩展参数容量。
- **CoTrain 模型**：在 Mosaic 训练架构基础上，额外引入下游排序模型的副本，共享用户塔，使嵌入同时受上游监督和下游表面目标约束，从而对齐特定消费任务。

**关键技术**：
- **多任务关系挖掘（MRM）**：计算所有任务标签间的 Spearman 秩相关系数，对高相关任务组（如 Like 和 Comment）构造复合多类标签（笛卡尔积），对连续值任务先分桶再组合。该复合标签使嵌入能编码更细粒度的用户意图，以最大化新专家的独特知识贡献。
- **余弦冗余损失（CRL）**：辅助损失项，最小化新嵌入与已有嵌入之间的余弦相似度，强制新嵌入落在正交子空间，增加信息增量。训练时采用从零逐渐增大的 warm-up 调度，避免影响主任务收敛。
- **无日志评估框架**：
  - **CoEval**：冻结用户塔，将其与下游排序模型副本联合训练，直接计算嵌入带来的 ΔNE，无需部署和特征日志，迭代速度提升 3–5×。
  - **User Tower Zero-Out**：将用户塔输出置零后观察上游模型 ΔNE，以隔离嵌入的边际贡献。
- **混合服务栈**：提供 CPU 在线推理、GPU 在线推理、GPU 离线推理三条路径，按专家特点选择。GPU 在线优化包括 AOTInductor 编译、预测器调优、模型拆分、2 小时 TTL 的 memcache 层，可将 GPU 服务使用降低 79% 并改善延迟。
