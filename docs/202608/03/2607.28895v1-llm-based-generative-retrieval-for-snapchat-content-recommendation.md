## 摘要
预训练大语言模型（LLM）因其丰富的语义先验、强大的序列建模能力以及有利的扩展行为，有望成为检索引擎。然而，在生产部署中将预训练LLM转化为生成式检索器面临若干挑战：模型必须学习预训练中不存在的内部项目词汇表，并在严格的延迟和成本约束下生成有效的项目标识符。我们通过设计并推出SnapLGR来应对这些挑战，这是一个用于Snapchat短视频推荐的基于LLM的生成式检索系统。该系统围绕三个主要设计构建。首先，我们从多模态项目嵌入构建语义标识符（SID），并通过基于个性化PageRank（PPR）的共参与对比学习增强它们，从而改善码本利用率、减少冲突并注入协同信号。其次，我们使用持续预训练（CPT）来在用户交互序列上进行监督微调（SFT）之前锚定引入的SID令牌。第三，我们通过TensorRT-LLM CUDA支持的束搜索和解耦的工作循环架构使SnapLGR服务变得实用。在一次在线A/B测试中，所推出的系统相对于现有的TIGER风格生成式检索基线，使观看时间增加了0.37%，花费时间增加了0.09%，深度会话增加了0.18%，深度会话独立用户增加了0.11%。然后，我们在固定分词器下分解这种离线差距，并量化模型架构、扩展和预训练带来的增益。总体而言，我们的部署表明，成功的生产级SnapLGR需要在表示学习、词汇表锚定以及高效训练和服务方面进行联合设计。

## Abstract
Pretrained large language models (LLMs) are promising retrieval engines because they combine rich semantic priors, strong sequence modeling capabilities, and favorable scaling behavior. However, turning a pretrained LLM into a generative retriever in production deployment raises several challenges: the model must learn an internal item vocabulary that was absent from pretraining, and generate valid item identifiers under strict latency and cost constraints. We address these challenges through the design and launch of SnapLGR, an LLM-based generative retrieval system for short-video recommendation at Snapchat. The system is built around three main designs. First, we construct semantic identifiers (SIDs) from multimodal item embeddings and enhance them with Personalized PageRank (PPR)-based co-engagement contrastive learning, resulting in improved codebook utilization, reduced collisions, and infused collaborative signal. Second, we use continued pretraining (CPT) to ground the introduced SID tokens before supervised fine-tuning (SFT) on user interaction sequences. Third, we make SnapLGR serving practical through TensorRT-LLM CUDA-backed beam search and a decentralized worker-loop architecture. In a live A/B test, the launched system increased View Time by 0.37%, Time Spent by 0.09%, Deep Sessions by 0.18%, and Deep Sessions Unique User by 0.11% relative to the existing TIGER-style generative retrieval baseline. We then decompose this offline gap under a fixed tokenizer and quantify the gains due to model architecture, scaling, and pretraining. Overall, our deployment shows that successful production SnapLGR requires joint design across representation learning, vocabulary grounding, and efficient training and serving.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：预训练大语言模型（LLM）在语义理解、序列建模和规模扩展上潜力巨大，但将其转化为生产级生成式检索器面临着三个关键挑战：
  - **分词器设计**：如何为海量视频语料构建语义标识符（SID），在压缩语义信息的同时避免严重 token 冲突（collision）。
  - **词汇接地**：SID 是不存在于 LLM 预训练词汇表中的新 token，模型需要先在语义上"锚定"这些 token，才能利用预训练知识进行推荐。
  - **高吞吐训练与服务**：LLM 计算开销大，在严格 GPU 预算下需实现频繁的增量重训练和大规模宽波束（wide-beam）推理。

- **研究含义**：论文旨在回答两个问题：
  1. 如何端到端地构建一个克服上述生产挑战的 LLM 生成式检索系统？
  2. 相比传统的 TIGER 风格（T5 encoder-decoder）基线，该系统在线业务收益如何，离线性能提升的来源是什么？

## 2. 方法论：核心思想与技术细节

### 2.1 系统总览
SnapLGR 由三个相互依赖的组件构成：
- 多模态行为感知 SID 分词器（§2.1）
- 两阶段 LLM 训练管道（CPT + SFT，§2.2）
- 高吞吐训练与推理基础设施（§2.4）

### 2.2 多模态、行为感知的 SID 构建
- **多模态嵌入**：使用 Qwen3-VL-Embedding-8B 将视频帧与 Gemini 2.5 Flash 生成的文本描述映射到共享嵌入空间（取前 1024 维，利用 Matryoshka 表示学习特性）。
- **残差量化（RQ-VAE）**：采用类似 Ju et al. 的架构，通过 L 级码本（codebook）将连续嵌入离散化为 L 个 token 的 SID，公式流程如下：
  - 编码器输出残差 \(r_i^1 = E(\text{LN}(e_i))\)
  - 每级选取余弦相似度最高的码字：\(z_i^\ell = \arg\max_c \text{cossim}(r_i^\ell, C^\ell[c])\)
  - 残差更新：\(r_i^{\ell+1} = r_i^\ell - C^\ell[z_i^\ell]\)
  - 使用硬前向、全码本直通估计器（hard-forward, full-codebook straight-through estimator）传递梯度，防止码本崩塌。
- **PPR 协同对比损失**：在用户-视频二部图上计算 Personalized PageRank（PPR）分数，构造高协同参与度的正样本对，通过对比学习将协同信号注入 SID 空间，公式为：
  \[
  L_{co} = -\frac{1}{B}\sum_{p=1}^B \log \frac{\exp(g_{i_p}^\top g_{i_p^+}/\tau)}{\sum_{p'=1}^B \exp(g_{i_p}^\top g_{i_{p'}^+}/\tau)}
  \]
  训练目标为：\(L = L_{rec} + \lambda_{com} L_{com} + \lambda_{co} L_{co}\)。

### 2.3 两阶段 LLM 训练管道
- **阶段一：继续预训练（CPT）**
  - 将 SID token 追加到 LLM（Qwen3-0.6B）词汇表，初始化嵌入为高斯分布（均值/协方差对齐已有嵌入）。
  - 冻结 LLM 其他权重，仅训练 SID 嵌入，任务为"给定 SID 生成视频文本描述"，以将 SID 锚定到 LLM 的语义空间中。
- **阶段二：监督微调（SFT）**
  - 在用户 SID 交互序列上进行全参数微调，采用 ChatML 格式，用户 prompt 为历史 SID 序列，assistant 输出为未来互动项，仅对 assistant token 计算 loss。
- **训练生命周期**：CPT 在初始训练阶段执行一次；SFT 进入每小时增量训练以保持时效性。

### 2.4 高吞吐训练与推理优化
- **训练优化（累积效果 3.63×）**：
  1. `torch.compile` 图编译（1.29×）
  2. FlashAttention-2 变长内核支持（1.47×）
  3. 动态序列打包（1.78×）
  4. 迁移至 H100 GPU（3.63×）
- **推理优化（累积效果 45.7×）**：

## 6. 主要结论与发现

- **SnapLGR 大幅优于 T5 基线**：离线 Pass@32 提升 2.27×、Recall@32 提升 2.40×；在线 A/B 中实现 View Time +0.37%、Time Spent +0.09%、Deep Sessions +0.18%、Deep Sessions Unique User +0.11% 的显著提升。
- **归因排序**（在固定 tokenizer 下）：
  - ① **Decoder-only 架构**是最大增益来源（13M 规模下 Qwen3 比 T5 高 1.51× Pass@32）；且不能仅靠扩大 T5 容量替代（220M T5 仅达 13M Qwen3 水平）。
  - ② **模型规模扩展**次之，Qwen3 在高容量区间仍在增长（60M→220M +14.3%），而 T5 已趋于饱和（+4.4%）。
  - ③ **预训练初始化 + CPT**提供最小但一致的增益（+0.62% 至 +1.51%）。CPT 将 RSA 从 0.016 提升至 0.322，但 SFT 后降至 0.167（接近无 CPT 的 0.162），说明 SFT 以协同信号塑造嵌入为主。
- **PPR 协同对比学习显著改善 SID 质量**：码本利用率从 31.8% 提升到 48.2%，唯一性从 16.8% 提升到 31.3%（P50 阈值即可，P75 略有进一步增益）。
- **系统优化效益巨大**：训练吞吐 3.63×、推理吞吐 45.7× 的提升，使 LLM 生成式检索在生产 GPU 预算下可行。

## 7. 优点与亮点

- **工业系统端到端视角**：将 tokenizer 设计、词汇接地、训练/推理系统优化视为联合设计问题，这在学术论文中较为少见，对产业有直接指导意义。
- **PPR 注入协同信号**：相比 PLUM 的随机对比对，PPR 基于图结构构造高质量正样本对，避免全局热门节点偏置，方法上有明显改进。
- **严谨的归因实验设计**：固定 tokenizer 分离架构/规模/预训练效应的做法科学干净；在匹配参数规模下对比 T5 和 Qwen3，结论具有较强的说服力。
- **量化了 CPT 接地效果的动态过程**：RSA 显示 CPT 建立语义对齐、SFT 重塑嵌入空间，定量揭示了"语义接地被行为微调部分覆盖"这一实际训练动力学。
- **推理系统优化量化充分**：从 Python 束搜索瓶颈分析到 TensorRT-LLM、worker-loop、异步 I/O 的分层优化和测速，工程叙事完整。
- **在线 A/B 提供了生产验证**：7 天大规模真实流量测试，报告了置信区间与 p 值。

## 8. 不足与局限

- **在线 A/B 归因混淆**：A/B 同时替换了 tokenizer、backbone 和 serving stack，尽管离线实验做了分项归因，但两者之间的映射未必完全一致；在线差距不能直接分解。
- **离线指标绝对水平较低**：Recall@32 仅 11.11%——即使相对 T5 提升 2.4×，从绝对推荐质量看仍有大量改进空间，论文未讨论这一低召回率对生产实际体验的潜在影响。
- **SFT 后语义接地衰减**：RSA 从 0.322 跌至 0.167，论文承认 SFT 主导性地覆盖了 CPT 建立的语义结构；CPT 的长期收益机制仍不明确，可能只是一种有利初始化。
- **SID 质量与检索性能的不完全相关性**：论文指出 MM tokenizer 在碰撞指标上较差却在检索中优于 MM+，说明碰撞指标不能完全预测端到端性能，这一矛盾未充分解释。
- **模型规模覆盖有限**：骨干仅为 Qwen3-0.6B，未扩展到更大 LLM（如 7B/72B），scaling law 外推结论限于小模型区间。
- **资源信息披露有限**：未报告训练总时长、GPU 总数量、推理延迟（P99）等关键运营指标，外部读者难以完整评估部署成本与可行性门槛。
- **短时窗口局限**：SFT 仅用 1 天数据评估，CPT 用 1 个月窗口，未展示跨更长时间范围的鲁棒性；论文也未报告模型时效性衰减或冷启动场景的表现。
